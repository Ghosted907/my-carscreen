## إعادة نشر السيرفر عند تحديثه

من PowerShell العادي على جهاز المستخدم، نفّذ ملف `scripts/deploy-relay.cmd`.
يستخدم أداة Cloudflare الرسمية `wrangler@4` من npm، وينشر ملف `relay/wrangler.jsonc` إلى العامل نفسه والحساب المحدد فيه.
قد تطلب الأداة تسجيل الدخول والموافقة في المتصفح؛ لا تضع API tokens في الكود أو في الدردشة.

الإعداد المطلوب في Cloudflare:

| العنصر | القيمة |
| --- | --- |
| العامل | `t1-remote-relay` |
| متغير الربط | `ROOMS` |
| الصنف | `T1Relay` |
| التخزين | SQLite (متاح في الخطة المجانية) |
| أول migration | `v1` / `new_sqlite_classes: ["T1Relay"]` |

بعد النشر، افتح `/health` وتأكد من `ready: true`، ومن ظهور `T1Relay` في صفحة Durable Objects وربط `ROOMS` في إعدادات العامل.
حالة health تثبت وجود الربط فقط؛ اختبار الهاتف واللانشر فعلياً هو الذي يثبت عمل التحكم.

## الاستخدام بعد اكتمال النشر

1. ثبّت النسختين الجديدتين فوق النسختين الحاليتين إذا كان توقيعهما متطابقاً. لا تحذف النسخ الحالية لتجاوز اختلاف التوقيع؛ احتفظ بالبيانات وحدد التوقيع الصحيح أولاً.
2. في اللانشر: الإعدادات ← التحكم من الجوال ← الربط عبر الإنترنت.
3. انتظر ظهور «متصل بالسيرفر»، ثم اختر «نسخ رمز الربط» أو «إظهار الرمز».
4. في T1 Remote: اتصال عبر الإنترنت ← الصق الرمز ← اتصل عبر الإنترنت.
5. جرّب أولاً قراءة بيانات السيارة أو مزامنة ملاحظة نصية، والجوال والسيارة على شبكتين مختلفتين.

شاشة السيارة يجب أن تكون قيد التشغيل، واللانشر متصلاً بالإنترنت. الخدمة لا تشغّل شاشة مطفأة بالكامل ولا توقظ مركبة بدون اتصال.
يبقى الاتصال المحلي متاحاً كما كان، ولا يستبدل اكتشاف الشبكة المحلية اختيار الاتصال السحابي تلقائياً.

## طريقة العمل

يفتح الطرفان اتصال WebSocket مشفراً إلى Cloudflare. لكل سيارة غرفة عشوائية مستقلة ومفتاحان مختلفان: مفتاح خاص باللانشر ومفتاح للجوال.
الرمز المعروض يحتوي معرف الغرفة ومفتاح الجوال فقط؛ لا يكشف مفتاح اللانشر. يُرسل التوثيق في ترويسة Authorization، ولا توضع المفاتيح في الروابط أو سجلات التطبيق.
يخزن السيرفر بصمات المفاتيح فقط، ولا يخزن أوامر التحكم أو قراءات المركبة. قد تحتفظ منصة Cloudflare بسجلات تشغيل الطلبات وفق إعدادات الحساب؛ الكود لا يسجل أجسام الرسائل أو المفاتيح.

تتغير جلسة الربط عند كل اتصال جديد. يغلق السيرفر الجلسة السابقة، ولا يحوّل ردها إلى جوال جديد. الأوامر تحمل ترتيباً متزايداً وتنتهي بعد عشر ثوانٍ من استلام السيرفر؛ يراجع اللانشر الصلاحية بساعة رتيبة مرتبطة بوقت السيرفر.
لا يوجد تخزين للأوامر أثناء الانقطاع، ولا إعادة إرسال تلقائية لأمر فشل. إعادة الاتصال تعيد الاستعلام عن الحالة فقط، وتبقى قواعد RemoteProtocol وRemoteActions والضغط المطوّل الحالية مطبقة.

لتغيير رمز الربط، اختر «تغيير الرمز» من شاشة السيارة. يُغلق اتصال الغرفة السابقة، ويجب إدخال الرمز الجديد في الجوال.

## التحقق المحلي

اختبارات السيرفر:

```text
node --test relay/relay.test.mjs
```

اختبارات أندرويد المعتادة:

```text
gradlew :t1remote:testDebugUnitTest :t1launcher:testDebugUnitTest :t1remote:assembleDebug :t1launcher:assembleDebug
```

بُني المشروع في البيئة المقيدة بتشغيل Gradle داخل JVM واحدة دون daemon، وتشغيل JUnitCore مباشرةً بعد تجميع اختبارات Kotlin، لأن اتصال Gradle بالـ daemon المحلي لم يكن متاحاً. استُخدم مخزن Gradle المحلي وأدوات Android SDK المثبتة. توجد نسخ محلية اختيارية من OkHttp وOkio للبناء دون إنترنت، وبصماتهما في `remote-protocol/libs/NOTICE.txt`. يجلب البناء في GitHub الإصدارات نفسها من Maven Central، وتُضمّن تراخيصهما في أصول التطبيقين.

اختبار `relay/runtime.test.cjs` يشغل بروتوكول الربط على workerd داخل Miniflare. يثبت اتصال الطرفين، ورسالة التعارف، ومرور الطلب والرد، ورفض مفتاح خاطئ. يحتاج تثبيت تبعيات `relay/package.json` وتشغيلاً يسمح باتصال العمليات المحلية؛ تشغيله المحلي في البيئة المقيدة تعذر بسبب منع هذا الاتصال، ولذلك ينفذ ضمن فحوص الإصدار في GitHub قبل النشر.
